# Invoice export

In `/admin/orders`, open an order and expand **Xuất hóa đơn** below its recorded total. **Hiện giá gốc** adds an optional original-price column; it defaults off. **In / lưu PDF** opens a separate printable document and the browser print dialog. The legacy order list and payment confirmation use the same exporter, in the current locale.

Original price means the sale price before the first tracked per-order manual adjustment, saved in `lines[].priceBeforeEdit`. The authenticated price-edit API captures the existing price only on an actual change, in the same write as the new price. Further edits preserve this snapshot, including an explicit unknown (`null`) or zero. Unchanged lines do not invent a historical baseline. Client input cannot supply this snapshot; the API compares the saved line array before updating so concurrent changes return `409 order_lines_changed`.

This is separate from the catalogue/pre-discount `listPrice` snapshot, production costs and private partner price floors. A missing snapshot displays `—`. Old price-change events contain the new grand total but not the previous line prices, so existing historical prices cannot be reliably backfilled. Current catalogue prices and discount percentages are never used to guess them.

Unit prices come from `lines[].price`. Line amounts use current quantity × current unit price, since staff price changes can leave older per-line total metadata stale. `estimatedTotal` remains the recorded order total; no tier, promo, VAT or delivery rule is reapplied. Any difference from the line subtotal is labelled generically as an adjustment to the recorded total, without inventing a tax or discount breakdown. Unquoted totals stay unquoted; zero amounts remain visible.

The invoice includes payment QR and bank details using the same centralized receiving account as the other payment pages. With a payment ledger, the QR uses its reference and remaining amount after recorded payments; without a ledger, it uses the recorded order total and order reference. Paid/zero/void/unknown or mismatched balances do not produce a payment QR. The staff drawer disables export until payment details have loaded. The printed document waits for the VietQR image to load (up to eight seconds); if loading fails, it shows the manual bank details instead of silently printing an empty code.

Only explicit order/customer/line fields enter the document, with HTML escaping. Costs, margins, commission statements and other private order fields are not copied. The existing VietQR image service receives the receiving-bank details, payment reference and amount only, with no referrer, customer name, contact or address. Export creates no database write, message or payment. Unsaved order edits disable export in the staff drawer. No migration, dependency or environment change is needed; the new snapshot is an additional field in the existing JSON order lines.

Verification, 23 October 2026: all 51 targeted tests (16 invoice/payment, 3 price-history helper, 32 real staff-route tests with mocked backend) and the production build passed. Tests cover the first/repeated/unchanged/zero/unquoted price edits, snapshot spoofing, failed and concurrent updates, saved totals and escaped/private data, plus payment references and partial/paid/invalid ledgers. A browser check of the generated sample invoice confirmed the 80,000 → 90,000 VND price pair and the loaded QR for a 1,300,000 VND remaining balance after a 500,000 VND payment. No real customer order or payment was changed. The actual OS print/save dialog was not exercised. The earlier export disclosure/checkbox check remains applicable.

Manual QA: export with the checkbox on/off, an older order without `priceBeforeEdit`, a retail discounted order, a bulk order, and an order whose price was edited twice (original must remain the first tracked baseline). Check the QR amount/reference for an unpaid, partially paid and fully paid ledger, and verify QR appears in the saved PDF. If pop-ups are blocked, allow them for this website and retry. The printout is a preliminary invoice; it does not replace an electronic tax invoice.
