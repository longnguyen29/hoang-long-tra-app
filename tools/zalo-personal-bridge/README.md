# Hoàng Long — Optional Personal Zalo Bridge (Mac mini pilot)

**Not an official Zalo integration.** Uses `zca-js@2.2.0`, which simulates Zalo Web. Its authors warn this may cause Zalo account suspension or permanent ban. No account upgrade removes that risk. **Do not start with the main, indispensable business account.** Consider a secondary account or use supported Zalo OA for commercial integrations.

## Safety by design
- Only inbound *text* in **explicitly allowed one-to-one chats** is forwarded. No groups, history scraping, profile harvesting, images or outgoing messages.
- No Zalo password, QR, cookies, session file or login token is sent to Hoàng Long's servers.
- Only this Mac runs the unofficial listener; no `zca-js` library is installed in the production Next.js app.
- A dedicated, revocable one-time bridge token authorizes ingestion to one locked-down HTTPS endpoint.
- When the bridge is disconnected the cloud cannot receive personal Zalo messages. **There is no guaranteed delivery** if Mac sleeps, Zalo invalidates the session or the listener is displaced. The in-memory retry buffer is lost on process exit.
- Do not send information from sensitive personal conversations or contacts who have not agreed to business record processing.
- Zalo Web can disconnect another listener; the upstream zca-js README states that only one web listener per account can run concurrently.

## Start (on your own Mac — not in ChatGPT's cloud)
1. On the live admin dashboard `/admin/customer-memory`, create an admin-only **Zalo personal bridge** pairing token; record it once, then close the pairing panel.
2. In this folder, `cp .env.example .env` and insert the token; keep `.env` only on your Mac. To discover one contact's ID, first set `BRIDGE_DISCOVER_CONTACT_IDS=1` and run the listener. Ask that contact to send a harmless test text: the terminal prints the contact ID locally **without forwarding message content**. Stop the listener, set `BRIDGE_DISCOVER_CONTACT_IDS=0`, then put the ID into `ALLOWED_ZALO_CHAT_IDS`. Do not enable all contacts by default.
3. With Node.js 22+, run `npm install --save-exact` and then `npm start`. Run `npm audit` and examine the dependency tree before you accept the risk.
4. A QR sign-in is initiated locally by zca-js. You must complete it yourself on the phone.
5. With one allowed test contact, send a harmless test message. Check the admin dashboard for a new `zalo_personal` thread and a draft. No outgoing customer message will be sent.
6. Stop with Ctrl+C. Revoke the pairing token in the dashboard to immediately deny future bridge traffic.

The `zca-js` library is not operated or endorsed by Zalo. If accounts are mission-critical, **prefer Zalo OA or manual import** instead of this approach.

## Operations
- Pairing credentials are generated by the authenticated owner through `POST /api/staff/customer-memory/bridge`.
- A manager can read status; only `admin` can create or revoke credentials.
- Cloud endpoint: `POST /api/webhooks/customer-memory/personal-zalo` with the created bearer token.
- A failed AI draft does not discard a captured message.
- This pilot does not yet provide durable local queueing or background LaunchAgent installation. Don't use it to monitor a high-volume live account unattended until those are addressed.
