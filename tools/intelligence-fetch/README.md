# Gate 0 research fetch prototype

Isolated, offline-only review copy adapted from `HoangLong_Intelligence_System_V6.zip` (`workers/` and the accompanying Node tests). Not wired into the application, cron, database or network service. No live fetch or deployment is authorized by the presence of these files.

Run `node --test tools/intelligence-fetch/*.test.mjs`.

Differences from the submitted V6 reference: robots policy normalizes unreserved percent-encoded octets and Unicode UTF-8 and is checked before every target redirect hop; DNS, response streaming and each request have a wall-clock deadline and abort; wildcard matching avoids an attacker-controlled backtracking regex; the HTML scanner handles unterminated tags in bounded passes; IPv4 DNS pinning supports the current Node lookup callback formats; best-effort contact redaction happens before the excerpt is truncated (it is not a guarantee of removal of all sensitive information); and the runner rejects page redirects before following them and rejects any remaining final URL mismatch before recording evidence (robots.txt redirects have separate policy).

The SQL candidate currently stores the original prospect URL as the observation URL and has no parameter for a redirected final source. The runner currently fails closed on page redirects before following them and on any remaining URL mismatch, including benign canonicalization, before recording evidence. Supporting redirects in a later version requires a reviewed database contract that preserves both the original URL/version used for stale checks and the actual final evidence URL. Tests use controlled mocks and a local HTTP server, not proof of live DNS pinning, Supabase/RLS, deployed runtime, robots parsing conformance, or application compatibility. The feature must remain disabled until independent security and staging checks are completed.
